# foods MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go and Postgres remote MCP server for logging food by talking to Gemini, with the same tools as [healthy-mcp-template](https://github.com/redSlug/healthy-mcp-template) from [Bradley Dettmer's post](https://www.bradleydettmer.me/blog/deploy-your-own-food-tracking-mcp/).

**Architecture:** One binary. `/mcp` is the official go-sdk Streamable HTTP handler behind `auth.RequireBearerToken`. The same server is a small OAuth 2.1 authorization server (RFC 8414 metadata, RFC 7591 registration, PKCE S256, non-rotating refresh tokens, revocation) that hands sign-in to Google and admits only `ALLOWED_EMAILS`. Redirect URIs are limited to Gemini's `oauth-redirect*.googleusercontent.com` hosts, `claude.ai` and loopback, so no consent screen is needed.

**Tech Stack:** Go 1.27, `github.com/modelcontextprotocol/go-sdk`, chi, gutil logging, GORM AutoMigrate on Postgres, `coreos/go-oidc`, `golang.org/x/oauth2`, embedded-postgres in tests.

## Global Constraints

- Full tool parity: search_foods, add_food, import_food, update_food, log_entries, update_log, archive_log, get_day, log_workout, update_workout, archive_workout, update_settings.
- Nutrients are computed by the server from grams; logs store grams only. Nothing is deleted, only archived.
- Every query is scoped by the user id from the OAuth token; no tool takes a user id.
- Logging tools require `client_request_id`; a repeat returns the first result.
- Google sign-in, allowlist by email. Host `foods.natwelch.com`.
